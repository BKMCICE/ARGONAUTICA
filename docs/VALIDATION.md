# 验证范围

本页概述原完整系统的实际结果，并说明当前源码导出可以支持的结论。当前目录未重新进行 FPGA 物理实现或实板验收。

## 原完整系统

完整配置曾在盘古 50K 开发板上完成以下检查：

| 项目 | 已测范围 |
|---|---|
| 诊断输入与参考 | 三轮完整 RAW 回传、独立量化及原生参考模型比较，检测头和全部框一致 |
| 自动循环 | 狗图 → 纯白 → 狗图，检测数 4 → 0 → 4；无需逐轮串口触发 |
| Flash 启动 | 完整有效镜像独立读回一致；实际开发板主电源周期后自动装入并完成三轮 |
| 结果显示 | 一分钟、60 个 1 Hz 解码 RGB 样本；检查了有结果、零结果与恢复结果三个阶段 |

生产循环版不逐轮回传所有像素。它以当轮 RAW／CHW 的 CRC 与 FNV 匹配已经完整验证的诊断参考，再比较两个检测头和全部检测结果。这与逐帧全像素回传是不同的证据范围。

狗图纯前向约 7.81 秒，按板端周期数和标称 100 MHz 换算；相邻轮起点观察间隔约 12.82～12.94 秒，包含 3 秒结果保持。输入 60 Hz 不是识别 60 FPS，也未据此给出准确率／AP 或长期温升结论。

## 软件整理检查

原完整源快照的便携构建器曾在新目录重建应用与启动 ROM，所得有效应用和 ROM 字节与保存版本一致。当前导出保留了软件源、模型数据和编译配方；`demo/software/build.py --check` 只检查软件输入身份，不编译、不访问设备。

`python tools/verify_source.py` 核对本仓库分发文件的保存字节，与完整原工程的硬件路径／时序门禁不同。结果页示例为原完整系统的实际采集：[有检测结果](assets/result-detections.png)、[零检测结果](assets/result-empty.png)。

## 当前源码的边界

本仓库未分发专有厂商 IP、已验位流和组合 Flash 镜像。上述历史结果不能作为缺少这些文件的公开目录已独立复现完整系统的证明。

恢复厂商依赖、重新综合或改变软件参数后，需要重新执行与改动相适应的仿真、数值对照、时序、管脚及实板验证。原系统曾通过的有限测试不等于完整 ISA 认证、准确率评测、全热插拔或长期稳定性认证。

## 本次展示源码的实际重编译

清理后的本仓库源码已在独立新目录使用 GCC 15.2.0 重新编译应用和启动程序。应用 BIN、启动 BIN 和 ROM HEX 与原已验身份逐字节一致，记录见 [软件重建摘要](../demo/software/verification.json)。这证明软件入口在移除硬件 IP 和历史目录后仍有效，不是新的 FPGA 物理实现或上板验收。
