# A31 可选滑窗提交原型（诊断专用，未采用）

正式仍为 A02 位流＋A25 固件。此目录不接入生产 YOLO 分派，也没有新增 PDS 构建开关。
`ENABLE_AI_WINDOW` / `ENABLE_WINDOW` 默认 0，只有 block 引擎开启时才能取 1。
诊断使用独立 ELF；生产 BIN 已重编译并与正式版本逐字节核对。

## 接口与所有权

在 AI_BASE 上新增以下**精确偏移**，其他原有地址、别名和字节使能语义保留。
未开启适配层的原 primitive 和 A02 均在 0x30 返回 0，驱动先探测再写入；
不支持时直接委托原 `conv3x3_rolling`，继续使用其原有 DONE 等待契约。

| 偏移 | 读 | 写（仅对新接口要求对齐、be=0xf） |
| --- | --- | --- |
| 0x30 | 0x41333131，A311 | 非法，置错并清空滑窗有效标记 |
| 0x34 | bit0 enabled / bit1 sticky error / bit2 seed complete / bit3 staged column / bit4 busy | bit0 设置 enabled，bit2 清 error；其他位必须 0。每次写都清 seed/stage，忙时拒绝 |
| 0x38 | 0 | bit31=0：低24位依次为新增 top/middle/bottom 字节，滑一列并启动；bit31=1：与已暂存列一起滑两列并启动。bit30:24 必须 0 |
| 0x3c | 0 | 低24位暂存 stride2 的第一列，最高字节必须 0；不能重复暂存 |

原 PIX0/1/2 的连续9字节仍按行优先排列；三个字自失效以来均写过后允许滑窗。
初次启用、权重/bias 更新、block 所有权切换、新接口错误、复位均要求重新写全窗口。
每行首个内部窗口及所有填零边界都走原三字 PIX＋CTRL，不跨行保留滑移状态。
stride2 的 0x3c 是第一新增列，0x38 是第二新增列；任何提交都会消耗暂存列，
包括 stride1 提交丢弃之前的暂存列。PIX/CTRL/模式写也会清暂存状态。

调用者独占 AI 单元及张量/参数，禁止中断处理程序并用此接口。计算中只轮询 CTRL
或 STATUS；适配层忙时其他读返回 0、写被拒绝并置错，不污染已接受任务。
原旧接口自行启动后的忙时写语义继续保留，但滑窗所有权失效。
复位会中止计算，清模式/有效性；数据 RAM 继续沿用 A02 的有效位保护。
驱动新增路径最多轮询 100000 次，错误立即返回，已经部分写出的输出无效，
必须由调用者恢复/复位硬件后再继续，不能把错误返回当一次成功推理。

## 实现代价

适配层保存72位窗口，并在内部依次转发 PIX0、PIX1、PIX2、CTRL，等待原核心完成。
新窗口先锁存，再逐字转发，避免同一时钟非阻塞赋值使乘法器取到旧窗口。
它减少的是 CPU MMIO 事务，内部仍有三字写入；每次滑窗对应7个适配状态周期，
原核心忙2周期。共享九路乘法器及三块 payload RAM，不增加 DDR 主端口。
融合启动使用 CTRL=1；软件维持原 Q24、bias、leaky、clip[-127,127] 和 CHW 写回。

`generate.py --check` 校验从生产滚动头文件和 A30 测试框架生成的副本，保留原
形状/跨度/别名检查及量化表达式，仅更换总线传输和内部滑窗循环。
主机 transport 模型不预测硬件周期；实际握手/忙周期由独立 RTL 和 RV32 SoC 测试核对。
