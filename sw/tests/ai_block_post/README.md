## 数值与结果布局

原MAC的int32输出先乘按通道signed32 multiplier，使用signed64中间值做Q24，
正负半整数均远离0舍入，再加signed32 bias，可选leaky（1677722 Q24），最后
clip[-127,127]。主量化用signed32×32乘法，原九路INT8 MAC不变。
负数leaky使用独立有界无符号支路：最终clip使幅值≥1265直接饱和为-127，
其余仅需11位幅值乘固定正系数；leaky_domain.py证明与原Q24/clip等价。
初版共享符号反馈路径曾出现实板负数leaky错误，保留失败证据，尚未证明综合根因。
若原Q24 narrowing/负号或bias int32加法超出定义域，则整个任务报错且不提供有效打包结果，
不模拟C未定义溢出。当前模型所有55个1×1层/4142通道的保守范围单独证明。

打包按[输出通道][空间像素]排列，每输出通道占ceil(pixels/4)个32位字；字内低字节
为首像素。每个通道末字未用字节为0，不把下一个通道的像素挤入尾部。原0x120
int32结果仍保留，后处理完成时把原RADDR恢复0；两种读回游标独立。

## 可选寄存器

0x28能力探测返回0x41333231（A321）；原primitive及A02在该偏移返回0且无副作用。
驱动在写入任何新寄存器前探测，不支持就调用原生产block算子。新寄存器要求
32位对齐且写字节使能0xf；旧接口的语义由原核心保留。

| 偏移 | 含义 |
| --- | --- |
| 0x200 | 读bit0 busy、bit1 done、bit2 error、bit3 packed-valid，bits11:8 multiplier有效位、bits15:12 bias有效位；写4清后处理状态，不清参数 |
| 0x204 | 写/读bit0 enable、bit1 leaky；其余位为0。每次写清参数/打包有效位，模式0关闭 |
| 0x208 | 参数通道地址0..3；写后清全部参数有效位，开始一个新输出批次 |
| 0x20c | 当前通道multiplier；写会清对应bias有效位 |
| 0x210 | 当前通道bias；须先写multiplier，写后通道地址加1 |
| 0x21c | 打包结果游标0..7 |
| 0x220 | 自动前进的打包结果读口，未完成/越界返回0并报错 |
| 0x224 | 本任务有效打包字数 |
| 0x228 / 0x22c | 后处理控制阶段周期 / 启动量化条目数，区别于原核心busy/软件轮询 |

参数未写时读mult/bias返回0；输出RAM仅由valid保护，复位不清载荷RAM。
开启后仍由原0x104 START启动MAC，待MAC完成再内部读取原结果并后处理，最后才
向CPU报告DONE。检查原核心错误、参数完整性和形状；忙时外部写入拒绝并置错。
原0x104 ACK清任务状态但保留参数，允许按通道参数与权重跨空间tile复用。

调用者独占AI单元和张量/参数，不允许中断并用。驱动沿用100000次有限DONE等待，
错误/超时传播为推理失败，不再回退重算；部分写出的输出无效，恢复硬件后重试。
开启后计算中只允许轮询状态；旧代码在模式0时继续使用原接口。

## 校验及构建

`generate.py --check`验证生产验证/缓存/打包循环的机械副本与host传输模型；新路径
只替换后处理传输和参数上传。所有phase采样编译开关保持0，诊断在完整算子外计时。最终对照参数与A25一致：
SMALL_PACK=1、PACK9=1、INPUT_BATCH=12；两组都使用相同输入/权重缓存策略。
主机参考读取独立CHW并用int64/除法舍入；model_domain.py另生成Python数学向量。

完整RTL/SoC及构建记录归档于项目validation。PDS候选使用
`pds/run_pds.ps1 -Ddr -Ila -AiBlock -AiQuant -ProjectDir <独立F盘目录>`，必须全新布局，
不能复用A02放置结果。未通过新配置的PDS时序和物理管脚核验之前不能下载。
正式采用还需要整网集成、实际TCM/栈、多图与实板验证，不能由本目录测试代替。
